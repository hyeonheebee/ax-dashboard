# 서울 AI 허브 AX 사이트 (직원용) — 설계 스펙

- 날짜: 2026-07-25
- 상태: 사용자 설계 승인 완료 (참석판 = 옵션 1 + 로그인 확장 준비)
- 목적: AI 허브 내부 AX·AI 리터러시 증진. 전직원에게 (1) AX 프로젝트 마일스톤 투명 공유, (2) 슬랙 3채널 활성 현황, (3) AI 세션 참석 도장판·뱃지 제공

## 0. 원칙 (제약)

1. **운영자 멘트 절대 금지** — 사이트의 모든 문구는 직원 대상 배포용 완성형. `data.json`의 `headline`/`watch`/`next` 등 운영자용 필드는 렌더링하지 않는다.
2. **랭킹 금지** — 참석자 정렬은 가나다순 고정. 서열·비교 UI 없음.
3. **은근한 동기부여** — 성취(도장·뱃지)는 클릭 뒤에 숨김. 전시가 아니라 발견.
4. **자동 갱신 최대화** — 기존 수집 파이프라인(회사 컴 → GitHub push, 매일 12·17시) 100% 재사용.
5. **중단도 투명하게** — 회계 자동화는 Plan A~C 시도 이력을 병기해 "검증 → 판단 → 전환" 서사로 공개.

## 1. 아키텍처

- **저장소**: 기존 `hyeonheebee/ax-dashboard` repo에 `site/` 폴더 추가. 기존 운영자용 `index.html`(루트)은 무수정.
- **배포**: 사내 VPS(지침봇 서버) nginx 정적 서빙. VPS에서 cron `git pull`(1분) → push만으로 사이트·데이터 자동 반영.
- **데이터 소스** (전부 클라이언트 fetch, URL은 `site/config.js` 한 곳에 모음 — B안(Flask API) 전환 시 config만 교체):
  - `data.json` — 기존 수집기 산출물 (무수정). 프로젝트 상태 + `channel_history` 사용.
  - `site/milestones.json` — 직원용 마일스톤 큐레이션 (프로젝트별 단계 정의·직원용 문구·Plan A~C 이력). 수동 관리.
  - `site/attendance.json` — 세션·참석·후기·뱃지 기록. 세션 후 수동 갱신(GitHub 웹 편집 or Claude), 추후 수집기 확장으로 자동화.

### A → B(Flask) 전환 통로

- 모든 데이터 접근은 `fetch(CONFIG.url)` 로만. 스키마 유지 조건으로 백엔드 교체 시 프론트 무수정.
- Google 로그인(seoulaihub.kr 도메인)은 지금 넣지 않되, "내 카드 선택" 로직을 `identity.js` 모듈로 분리해 두어 나중에 GIS/OAuth로 교체 가능하게 한다. 전환 트리거: 참석자 직접 체크인, 진짜 비공개 프로필, 실시간 알림이 필요해질 때.

## 2. 섹션 ① AX 마일스톤

4개 트랙, 가로 단계 진행바(완료 점 → 현재 점 강조 → 미래 점 흐림):

1. **지침검수봇**: 기획 → 파일럿 → VPS 24/7 가동 → 지침 검수·반영(현재) → 8월 정식 배포 → 피드백 루프
2. **회계 자동화 (종료 수순)**: Plan A~C 시도 이력을 접힌 상세로 병기. 타임라인 초안은 `project_history` 25일치에서 재구성 후 사용자 사실검수. 서술 톤: "여기까지 검증했고, 1인 규모를 넘는 과제로 판단해 작은 단위 자동화로 전환."
3. **AI 리터러시 세션**: 5회차 진행 현황 (섹션 ③과 연동, 1회차 완료)
4. **작은 단위 자동화**: 입퇴실&만족도 자동화(완료) 등 완료/진행 목록

상태 라벨은 `data.json`에서 자동 매핑(키: `gcb`/`accounting`/`literacy`/`attendance`), 단계 정의·문구는 `milestones.json`.

## 3. 섹션 ② 슬랙 채널 현황판

`channel_history` 그대로 사용: 3채널 카드(멤버·글·댓글·반응·인기 이모지) + 일자별 참여 추이 차트(Chart.js). 이미 자동 갱신.

## 4. 섹션 ③ AI 세션 참석 현황판

- 공개 화면: 참석자 **이름만** 가나다순 나열 (도장 수 비노출)
- 이름 클릭 → 카드 펼침: 도장판 ①~⑤(참석 회차 스탬프 애니메이션, 미참석 미래 회차는 빈 칸 — X 표시 금지) + 스트릭 🔥(현재 연속 횟수만, 리셋 압박 문구 금지) + 뱃지
- 첫 방문 시 "내 이름 선택" → localStorage 저장 → 내 카드 상단 고정 (로그인 없는 "내 프로필" 감각)
- **뱃지 6종** (개인 성취 기준, 비교 없음):
  - 🌱 첫 발걸음 — 1회 참석
  - 🔥 연속 출석 — 2회 연속
  - ⚡ 하프 마스터 — 누적 3회
  - 🏆 풀 코스 — 5회 전체 참석
  - ✍️ 후기 크리에이터 — 슬랙 스레드 후기 작성 (회차 도장에 ✍️ 마크 중첩)
  - 🚀 메이커 — 실습 결과물 공유
- 뱃지·스트릭 계산은 attendance.json에서 클라이언트가 파생 (뱃지를 데이터에 하드코딩하지 않음 → 규칙 변경 시 일괄 반영)
- 실명 표기 (슬랙 실명 문화 기준)
- 초기 데이터: 1회차(2026-07-24, "매직 프롬프트로 업무 도구 만들기") — 장문석·이슬기·정준호 (후기 작성 확인됨). 전체 명단은 사용자가 추후 제공 시 교체.

### attendance.json 스키마

```json
{
  "program": {"title": "AX 실습 시리즈", "total_sessions": 5},
  "sessions": [
    {"no": 1, "date": "2026-07-24", "title": "매직 프롬프트로 업무 도구 만들기", "held": true}
  ],
  "members": [
    {"name": "장문석", "attended": [1], "reviews": [1], "maker": []}
  ]
}
```

`attended`/`reviews`/`maker`는 회차 번호 배열. 여기서 도장·스트릭·뱃지 전부 파생.

## 5. 참석 기록 갱신 플로우

- 지금: 세션 후 후기 스레드 확인 → `attendance.json` 수정 (GitHub 웹 편집 or Claude에게 요청) → push → VPS 자동 반영
- 추후: 회사 컴 수집기가 세션 공지 스레드 댓글 작성자를 자동 추출하도록 확장 (확장 스펙을 `docs/collector-extension.md`로 남김)

## 6. 게이미피케이션 이론 반영

- 디지털 뱃지: 역량·경험 증명 언어("~달성", "~크리에이터"), 장식이 아닌 의미 부여
- 내적동기(자기결정이론): 유능감(도장 누적)·자율성(내 카드 선택, 노출은 본인 클릭)·관계성(세션 공동 경험) 자극. 외적 보상·서열 배제
- 듀오링고 스트릭: 연속성 시각화는 차용하되 손실회피 압박(끊김 경고)은 제거 — 누적 성취 프레임만

## 7. 성공 판단

- 각 프로필 클릭 시 뱃지·도장이 명확히 보이고 스탬프 애니메이션 동작
- data.json push → 사이트 자동 갱신 (수동 개입 0)
- attendance.json 한 파일 수정만으로 도장·스트릭·뱃지 전체 자동 재계산

## 8. 테스트

- 로컬: `python3 -m http.server`로 site/ 서빙, 3섹션 렌더·클릭 인터랙션·모바일 뷰 확인
- 데이터 엣지: 세션 0회차만 있을 때, 멤버 참석 0명, channel_history 결손일 처리
- 배포 후: VPS URL에서 fetch 경로(CORS/캐시버스트) 동작 확인
